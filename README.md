# ComfyUI-AccelSwitch

ComfyUI 顶栏补丁，七件事：

1. **顶栏一键切换全局注意力加速后端**（启动默认 / Kitchen INT8 / SageAttention / SageAttention3 / FlashAttention / xFormers / PyTorch / SubQuadratic / Split）
2. **顶栏整体缩放**（下拉菜单里拖滑块，50%~100% 每 5% 一档连续可调，解决顶栏太占地方）
3. **工作流保存时快照 + 打开自动套用后端 + 一键恢复**（所有节点参数 + **连线与节点位置**；点恢复不改后端、不改顶栏缩放）
4. **后端微基准**（固定合成形状的裸注意力计时，列出各后端该形状下的 kernel 耗时）
5. **常用参数模板**（把当前画布参数 + 各节点旁通/忽略状态存成命名模板，菜单一键填回）
6. **重跑上一个任务**（原样重跑 / 换随机种子重跑 / 把参数填回画布（按工作流分开记）/ 复制上一次的 API 参数）
7. **给所有媒体加载节点加「无」选项**（图像 / 视频 / 音频节点的文件列表最前面多一个空选项）

- 不注册任何工作流节点
- 不需要任何额外依赖（纯标准库 + ComfyUI 内部接口 + 原生前端组件）
- 不改动 ComfyUI 核心文件——**删掉整个文件夹即完全移除**

## 本次更新（v1.4.0）

- **恢复 = 画布状态还原**：除了节点参数 / 旁通 / 图像，现在把**连线状态**和**节点位置、大小**也一起回放到保存那一刻——保存时哪根线没接，恢复后还是没接；保存后新接的线会被断回去。不新建 / 不删除节点（保存后新加的节点留在画布上，它自己的连线也不动）
- **快照归属修复**：恢复只认「当前工作流自己」的快照。以前点某个工作流的恢复，有可能套进别的文件最近保存的那份内容（参数、旁通、图像一起串），现在跨文件一律拒绝，宁可什么都不改
- **恢复不再切换加速后端**：后端只在你打开工作流时自动套用，点「恢复」保持当前顶栏选择
- **参数模板改存服务端并按工作流隔离**：`user/AccelSwitch/presets.json`，跨浏览器 / 清缓存不丢，每个工作流最多 20 个；工作流另存为时模板跟着迁移
- **「把上一个任务的参数填回画布」按工作流分开记**：A 跑完再跑 B，回 A 点它拿到的仍是 A 那次，不会被 B 顶掉（最多记 12 个工作流）
- **恢复结果面板精简**：只显示工作流 / 恢复节点数 / 保存时间；只有真的接不上线、节点缺失时才多一行警告

## 功能一：加速切换

顶栏出现一个「恢复」图标 + **当前后端简称徽章**的按钮（与「运行 ▾」同款 SplitButton）：

- **点主体**：一键恢复**当前工作流**上次保存的样子（所有节点参数 / 连线状态 / 节点位置；不改加速后端、不改顶栏缩放；只认本文件的快照）
- **点 ▾**：弹出完整列表，✓ 为当前项；未安装/硬件不支持的后端会灰显，点了会提示不可用
- **悬停主体**：显示当前后端全名和快捷键说明
- **`Ctrl+Alt+A`**：循环切换后端；**`Ctrl+Alt+R`**：一键恢复快照；**`Ctrl+Alt+P`**：重跑上一个任务；**`Ctrl+Alt+Shift+P`**：换种子重跑（输入框内不会触发）

可选后端列表包含所有已知后端（由 ComfyUI 注意力注册表决定可用性），灰显项不可选。

### 切换机制（三条官方通道互补）

1. 重写 `comfy.ldm.modules.attention.optimized_attention / _masked` 全局——影响所有调用时读取该全局的路径（CLIP、图像编码器等），即时生效；
2. 对已加载模型调用核心自带 `ModelPatcher.set_model_optimized_attention`，写入 `optimized_attention_override`——`wrap_attn` 每次注意力调用最先检查它，对已加载模型即时生效（**包括 qwen_image 等捕获式导入的模型，这是唯一对它们有效的机制**）；
3. 钩住 `LoadedModel.__init__` + `CFGGuider.__init__`——之后新加载 / 懒加载的模型自动带上覆盖（guider 钩子是关键：`CFGGuider.sample()` 开头会深拷贝 model_options，晚于它的懒加载不能错过）。

**工作流内节点自带的覆盖优先**（XB sage / BlockCache-T8 / ModelAttentionBackend 等节点设的覆盖不碰、不受影响）。

选择存包目录下的 `state.json`，重启 ComfyUI 自动恢复。

## 功能二：顶栏缩放

同一个 ▾ 下拉菜单底部有「顶栏缩放」滑块（默认 80%，范围 50%~100%，步进 5%）：

- 拖动实时预览，松手保存；整个顶栏（命令栏 + 队列 / 任务浮层）按 CSS zoom 等比缩放——布局级缩放，文字重新渲染不模糊
- 菜单弹层挂在页面 body 上，不跟着顶栏一起缩：**拖滑块时菜单/滑块不会被缩小、位移而从鼠标底下跑掉**
- 缩放值记在浏览器 localStorage，刷新 / 重启不丢，只影响你自己的浏览器
- 只在新版 Vue 前端（ComfyUI 0.4x）生效；老前端下静默不生效，不影响其他功能

## 功能三：保存时快照 / 一键还原画布

每次你点 ComfyUI 的「保存工作流」，本插件会把那一刻的设置存一份快照到**服务端** `user/AccelSwitch/snapshots.json`（跟随 ComfyUI 用户目录，**换浏览器 / 清缓存都不丢**；浏览器 localStorage 只作兜底缓存）：

- **加速后端**：当时顶栏选的是哪个后端（只在**打开工作流**时自动套用，点「恢复」不改后端）
- **所有节点参数**：每个节点的 widget 值（**含图像节点选的图**）、旁通状态（mode）、标题
- **画布布局**：每个节点的位置 / 大小 / 层级，以及**全部连线**（保存时哪根线没接，恢复后也还是没接）
- （顶栏缩放只随快照记录，**恢复时不会套用**——缩放大小时刻由滑块自己控制，点恢复不该把顶栏大小改回去）

下拉菜单里的 **「↺ 恢复上次保存的样子」** 一键把这些还原到当前工作流：

- 节点**按「类型 + 同类型序号 + widget 名称」安全匹配**（不再按数字 ID——ID 跨工作流会撞车，曾导致把 T8 缓存节点的 `0.08/0.1/0.85` 套到 CLIP 节点上）。类型对不上、名称对不上、值类型对不上的一律跳过，绝不张冠李戴；跳过详情写进浏览器 Console
- 每个 widget 按**保存时的名字**找回对应值（而非按当前位置硬套），同类型多个节点（如 8 个图片加载节点）按画布坐标一一对应，互不串值
- 节点参数用 LiteGraph 官方 `node.configure()` 还原（这是新版前端唯一能正确驱动 widget 恢复 + 节点 `onConfigure` 钩子的路径），并严格按「类型 + 同类型序号」先匹配好节点，不会张冠李戴
- **图像 / 视频 / 音频加载节点**：新版 ComfyUI 前端用一个全局 store 统一管理"每个节点显示哪张图"，光改 widget 值不会更新它——这正是"值恢复了但旧图还挂着、按 F5 才对"的根因。恢复时会用快照的值直接更新这个 store（走前端自己的刷新路径），再清掉 canvas / DOM 上残留的旧图并延迟重建，**不用手动刷新页面**
- **自定义加载图像节点**（如「加载图像 孤海 LoadImageGoohai」）：这类节点保存工作流时会把空图状态存成 **0 字节占位图**（`vrgdg_placeholder_i2i.png`）。如果快照里是这种占位图、也没抓到真实预览图，说明**保存时这个节点本来就是空图**——恢复时会把当前画布上的图**清掉、还原成空图状态**：临时把 widget 值置空触发节点自己的清空链（清掉内部 `displayed`/`source`），再设回占位图，同时清掉 canvas 与 DOM 上的残留预览层。反之若快照里有真实图源（新版本保存会抓 `preview_urls`），则正常恢复那张图
- **图像输出 / 保存节点**（SaveImage、PreviewImage、SaveAnimatedWebP 等）：这类节点的预览是运行结果、不随快照保存，恢复时也会把当前残留的旧预览清掉（不让它继续挂在节点上），和加载图像节点的处理保持一致
- 只覆盖当前画布里类型匹配的节点的 widget 值 + 旁通状态（mode）+ properties；**不会新建 / 删除节点**
- **连线与位置也会还原**：快照里记了每个节点的 `pos/size/order` 和全部连线（两端用「类型#序号」身份键表示、插槽按名字匹配）。恢复时对「两端都在快照里」的连线，先断开再按快照重建——所以**保存时没接的线，恢复后还是没接**；保存后你新接的线会被断掉，保存后断开的线会被接回来。节点位置 / 大小也一起回到保存那一刻
- **保存之后新加的节点不会被删**，它自己连出去的线也不动（本次恢复只回放快照覆盖范围内的连线）；若新线占用了快照里要接的那个输入口，以快照为准，先挤掉再接回
- **分组控制节点（孤海「忽略多组」/ Fast Groups Muter 之类）特殊处理**：这类节点靠读其它节点的 mode 推导「每组是开还是关」，所以①它自己永远不会被恢复成忽略/旁通（快照里就算是静音状态也强制恢复正常，否则整个分组开关会直接失效）；②它放在最后恢复，等其它节点的 mode 都还原完再 sync，显示的分组开关才和画布一致
- **旁通 / 忽略是按"上次保存工作流那一刻"还原的**：保存之后你要又手动开关过节点或分组，点恢复就会把它们改回去——想保持当前状态，**先保存一次工作流再点恢复**。恢复面板会写明"旁通/忽略: N 个节点改回上次保存时的状态"，N 为 0 就说明本来就和快照一致
- **点「恢复」不改加速后端**（后端由顶栏自己控制，`Ctrl+Alt+A` 才是切后端）
- 快照按工作流文件路径分别保存，菜单悬停提示里能看到是哪个文件、多少个节点
- **恢复只认「当前工作流自己」的快照**：切到另一个工作流后点恢复，绝不会把别的文件最近保存的那份套进来；当前文件没有快照就**什么都不改**，只提示"本工作流还没有快照，先 Ctrl+S 保存一次"。多标签页同时开也一样——每份快照都挂在它自己的文件路径下
- **打开工作流时自动套用**该文件保存时的「后端」（节点参数仍来自工作流文件本身；顶栏缩放保持你当前的值，不会被改）
- 恢复完成会弹出可见的确认面板；`Ctrl+Alt+R` 快捷键同样能恢复

> 这个功能是「画布状态快照」：**参数 + 旁通 + 连线 + 节点位置**都会回放，但它**不新建 / 删除节点**。保存之后新加的节点会留在画布上（它自己的连线也不动）；快照里记着、但画布上已经删掉的节点，相关连线会被跳过并在面板里计数。老版本存的快照没有布局数据，只能恢复参数——`Ctrl+S` 存一次再恢复就完整了。快照服务端最多保留最近 30 个工作流；连线和位置数据只存服务端（不进 localStorage，避免挤爆 5MB 配额）。

## 功能四：后端微基准（注意：不是真实出图速度）

下拉菜单里有两个入口：

- **「⚡ 后端微基准（合成）」**：默认 2 次预热 + 5 次计时，**1024 token / 24 头 / 128 维 fp16**
- **「⚡ 微基准：Qwen 大形状」**：4096 token / 24 头 / 128 维 bf16，更贴近 Qwen Image 2.1 的注意力形状（显存占用更高）

后端逐个跑同一份合成 q/k/v 的裸注意力函数，然后：

- 按耗时排序，**同时写到两处**：① 屏幕右下角结果面板；② 服务端日志，搜 **`后端跑分`**（`user/comfyui.log` / 启动器控制台）
- 只直接调用注册表里的注意力函数，**不修改当前后端、不碰已加载模型**，跑完自动清缓存
- 需要 CUDA；不可用的后端单独标 error，不影响其他项
- 请求体可覆盖参数（含 dtype）：`{"warmup":2,"iters":5,"tokens":4096,"heads":24,"dim":128,"dtype":"bf16"}`

### 这个数字能说明什么、不能说明什么

**能**：同样形状下，哪个后端的内核本身更快（数字越小 = 该形状下裸内核越快）。

**不能**：它**不等于你工作流的真实出图速度**。负载是固定形状、无 mask 的随机张量，没有真实模型的注意力掩码、块缓存、量化权重布局、序列长度分布。

**形状一变，排名就会反转**。实测同一台机器：

| 形状 | xFormers | Kitchen INT8 |
|---|---|---|
| 256 token / 8 头 / 64 维（旧默认值） | **0.119ms**（最快） | 0.214ms |
| 1024 token / 24 头 / 128 维（新默认值） | 0.503ms | **0.223ms**（最快） |

**判断哪个后端对你更快，请以 AccelLog 的真实运行数据为准**：`[加速汇总]` 的采样耗时、`[节点耗时]`（日志搜这两个关键词）。

另外，如果你的工作流用 **Qwen T8 / XB sage / ModelAttentionBackend** 这类节点，它们自己就设置了注意力路由（例如 T8 的 `sage/kitchen 混合`），**顶栏切换会被这些节点覆盖、进不了采样主路径**——这时切换后端不改变出图速度，微基准排名更与你无关。从 `[加速日志]` 的「来源」一栏能看出这一刀到底是谁决定的。

## 功能五：常用参数模板

下拉菜单里用一条分隔线和其它功能隔开，提供三件事：

- **＋ 保存当前参数为模板…**：输个名字（如「Qwen 出图参数」），把当前画布**所有节点的普通 widget 参数**（prompt、步数、CFG、尺寸、各类开关等）**以及每个节点的旁通 / 忽略状态**抓成一份模板
- **★ 模板名**：点一下就把保存时的参数和旁通 / 忽略状态一起还原到当前画布
- **✕ 删除参数模板…**：从下拉列表选一个删掉

要点：

- **模板按工作流隔离**：每个工作流只显示属于自己的模板，切换/打开另一个工作流时菜单自动换成它的模板，互不串用
- 模板存在**服务端** `user/AccelSwitch/presets.json`，跨浏览器 / 清缓存不丢，每个工作流最多 20 个
- 按「**节点类型 + 同类型序号 + widget 名称**」匹配填值；当前画布没有对应节点或参数名时会跳过，绝不张冠李戴
- **旁通（紫）/ 忽略（灰）状态跟着模板走**：保存时是旁通的节点，套用后还是旁通；保存时是正常的节点，套用后会取消当前的旁通/忽略，回到正常
- **不含图像 / 上传文件类参数**，也不改加速后端、顶栏缩放、节点增删连线——它只管普通参数和节点状态，和「恢复上次保存的样子」是两回事
- 套用后右下角面板会显示「填入 N 项 / 还原旁通忽略 N 个 / 跳过 N 项」；跳过的多是当前工作流没有的节点，属正常
- 旧版本保存的模板没有记录旁通状态，套用时面板会提示，重新保存一次即可

## 功能六：重跑上一个任务 / 复制上一次参数

下拉菜单里另有一条分隔线，管的是**服务端真正执行过的那份任务**（不是画布当前状态）：

- **↻ 重跑上一个任务（同参数）**：把上一次提交的完整任务原样再入队——节点参数、种子都不变，结果应与上次一致。适合输出文件丢了、或换个加速后端重跑对比真实采样耗时。`Ctrl+Alt+P`
- **🎲 重跑上一个任务（换随机种子）**：同上，但把所有 `seed` / `noise_seed` 换成新的随机值，**不用改画布直接「再来一张」**。`Ctrl+Alt+Shift+P`
- **⇩ 把本工作流上一个任务的参数填回画布**：按「**节点 id 相同 + 节点类型相同**」双重校验，把**当前工作流自己**上一次运行时的参数写回当前画布对应节点。只写参数，**不改连线、不改加速后端、不改顶栏缩放**
- **⧉ 复制上一个任务参数**：把最近一次任务的 API 格式参数（JSON）复制到剪贴板，同时打印到 F12 console，方便存档 / 贴给别人排查

要点：

- **「填回画布」按工作流分开记**：A 跑完再跑 B，回 A 点这个功能拿到的仍是 **A 那次**，不会被 B 的参数顶掉（两份工作流的节点 id 都从 1 起，混用就会把 B 的参数写进 A）。没在这个工作流跑过时会直接提示"本工作流无运行记录"，不会拿别的工作流的顶上。最多同时记 12 个工作流（LRU 淘汰）
- 任务来源：提交时拦截 `POST /prompt` 抓原始请求体（就是服务端真正跑的那份）；**刷新过页面**后内存里没了，「重跑 / 复制」会自动回退查 `/history` 取最近一条（这一条不分工作流），「填回画布」则宁可提示无记录也不跨工作流取
- **「填回画布」的匹配是双重的**：id 和类型都对上才写，一个都没命中会直接提示"当前画布多半不是产生这个任务的那份工作流"；命中率低于 60% 也会警告。连线输入（prompt 里数组形式的）一律跳过不动
- 只记在内存、不写 localStorage——一个工作流的 API prompt 可能几百 KB，写进去会挤爆浏览器草稿配额
- 入队时用当前浏览器的 `client_id`，所以进度条 / 预览照常推到这个页面
- 如果上次是「只运行选中的输出节点」（部分执行），重跑会跑**整张图**（提交的 prompt 是完整的，只是少了服务端裁剪参数）
- 换种子重跑**只改服务端这次任务**，画布上的种子值不会跟着变；想保住这组参数请用「保存当前参数为模板」
- 入队被服务端拒绝（缺模型、参数非法等）时，右下角面板会列出具体节点和原因，不会静默失败

## 功能七：给所有媒体加载节点加「无」选项

所有**能加载图像 / 视频 / 音频的节点**（原生 `LoadImage`、`LoadImageMask`、`LoadImageOutput`、`LoadVideo`、`LoadAudio`、VideoHelperSuite 的视频节点、各类自定义加载节点……），点开文件下拉列表，**最前面多一个「无」**。

- 原生加载节点只有"选文件"，没有"空"这个状态；而"空图"是你工作流里真实存在的状态（保存工作流时本来就是空的）。现在可以直接把它显式置空
- 选中「无」会**顺带清掉节点上残留的画面**（canvas 上的 `node.imgs`、前端 `nodeOutput` store、孤海那类节点内部的 `displayed` 缓存），不会让旧图继续挂着
- 孤海这类本来就自带「无」的节点不重复加，只补上"选无 → 清画面"的钩子
- **恢复快照时把「无」当空图处理**：不再拿字符串 `无` 去拼 `/view` URL，直接还原成空图状态

判定规则（不会误伤模型选择框）：

- 列表里只要出现图片 / 视频 / 音频扩展名（png、jpg、webp、mp4、webm、mp3、wav…）→ 认定是媒体选择框，加
- 列表为空（输入目录里没文件）时，靠「输入名（image / video / audio / file…）+ 节点类别（image / video / audio / animation / loaders）」判断
- 列表里是 `safetensors` / `ckpt` / `gguf` 等模型权重 → **一定不加**（Checkpoint、LoRA、VAE 选择框保持原样）

⚠️ 注意：选「无」只是把节点置空。**如果你让这个节点参与执行，原生加载节点会报 `Invalid image file: 无`**（服务端校验），这是预期行为——表示这个输入你还没给图。孤海那类原生支持空图的节点不受影响。

实现上走了两条通道互补，前端「刷新节点定义」把取值列表整个换掉后也能自动补回来（看门狗每 ~10 秒兜一次，幂等）。

## HTTP API

```text
GET  /accel_switch                      → {"current": "...", "available": {...}, "all": {...含 available 标记}, "startup_default": "..."}
POST /accel_switch  {"backend": "sage"} → 切换并返回新状态（auto = 恢复启动默认）
POST /accel_switch_benchmark  {"tokens":4096,"dtype":"bf16"} → {"ok": true, "shape_desc": "...", "params": {...}, "results": [{"label": "...", "ms": 0.123}, ...]}
GET  /accel_switch_snapshots            → {"ok": true, "snapshots": {"workflows/xx.json": {...}, ...}}
POST /accel_switch_snapshots  {"file": "workflows/xx.json", "snapshot": {...}} → 写入快照（最多保留 30 个）
GET  /accel_switch_presets?workflow=workflows/xx.json → {"ok": true, "presets": {"模板名": {...}}}（该工作流的模板）
POST /accel_switch_presets  {"workflow":"workflows/xx.json", "action":"save"|"delete", "name":"...", "preset":{...}} → 保存 / 删除（每个工作流最多 20 个）
```

## 已知边界

- VAE 注意力不跟随切换（保持启动时的后端，VAE 解码耗时占比极小）
- 不走 CFGGuider 的自定义采样循环（部分视频类 wrapper）不生效
- CLIP 文本编码器注意力跟随全局切换
